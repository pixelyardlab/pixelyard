Dasselbe Raster wie bei der Hardware: was der Dienst tut, warum er so eingerichtet ist,
und was dabei schiefging oder beinahe schiefgegangen wäre. Am Ende stehen die zwei
Konfigurationszeilen, auf die es bei der Sicherung und beim Ausstieg ankommt.

<Bauteile>

<Bauteil rolle="Grundlage" titel="TrueNAS Scale" modell="Version 25.10 · Dateisystem ZFS">
Trägt Speicher, Snapshots und die Container für alle Dienste. Ein Datensatz pro Person
mit eigener Grössenbeschränkung, dazu getrennte Bereiche für Anwendungsdaten und Scans.
<Falle>Der Zuschnitt entscheidet, was ein Snapshot überhaupt erfassen kann. Ein Unterbereich, der kein eigener Datensatz ist, fällt still aus jeder Sicherungsregel heraus.</Falle>
</Bauteil>

<Bauteil rolle="Fotos" titel="Immich" modell="Version 3.1 · Erkennung über OpenVINO auf der eingebauten Grafikeinheit">
Ersetzt die Foto-Cloud vollständig: automatischer Upload vom Handy, Gesichter, Orte,
Suche nach Bildinhalt.
<Falle>Die Erkennung liess den Datenbankabzug von rund 12 MiB auf rund 360 MB wachsen — Faktor 30. Wer die Aufbewahrungsregel nicht mitzieht, füllt still den Speicher mit Sicherungen.</Falle>
</Bauteil>

<Bauteil rolle="Dokumente" titel="Paperless-ngx" modell="Version 3.0.5 · 15 Schlagworte · 10 Dokumenttypen · vier Einwurfwege">
Texterkennung, Volltextsuche, automatische Vorschläge für Absender und Typ. Die
Gliederung lebt in Schlagworten statt in Ordnern — ein Dokument kann zu drei Themen
gehören.
<Falle>Ein Schlagwort, das den Zugriff steuert, darf nie automatisch vergeben werden — sonst entscheidet ein Vorschlagsalgorithmus, wer was sieht.</Falle>
</Bauteil>

<Bauteil rolle="Sprachmodelle" titel="Ollama" modell="Modelle qwen3:8b und qwen2.5:7b · 8,42 s Ladezeit · 20,8 Token/s">
Läuft direkt auf dem kleinen Rechner, nicht in einem Container. Cloud-Modelle und
Websuche sind ausgeschaltet — der Dienst ist eine Vertraulichkeitsschleuse, keine
Sparversion.
<Falle>Der Dienst nimmt einen Zugriffsschlüssel entgegen und prüft ihn nicht. Wer ihn im Netz freigibt und sich auf den Schlüssel verlässt, hat keine Zugangskontrolle, sondern eine Höflichkeitsform.</Falle>
</Bauteil>

<Bauteil rolle="Abläufe" titel="n8n" modell="Version 2.36 · Ausführung in getrennten Prozessen · Schutz gegen Anfragefälschung eingeschaltet">
Die Werkbank für alles, was regelmässig oder auf ein Ereignis hin passieren soll:
Fristen, Erinnerungen, Übergaben zwischen Diensten.
<Falle>Ein Ablauf, den man einem Sprachmodell als Werkzeug freigibt, wird vom Modell ausgelöst, nicht von einem Menschen. Was etwas verändert, braucht eine enge Positivliste oder eine Rückfrage.</Falle>
</Bauteil>

<Bauteil rolle="Ausser Haus" titel="Verschlüsselte Kopie" modell="Backblaze B2 · client-seitig verschlüsselt · sieben Aufgaben, nachts">
Rund zwei bis drei Franken im Monat. Die Verschlüsselung passiert zu Hause — der
Anbieter bekommt Datenblöcke, keine Dateien.
<Falle>Der Übertragungsmodus ist Abgleich, nicht Kopie. Wer eine Datei zu Hause löscht, löscht sie damit auch dort. Das ist gewollt — aber man muss es wissen.</Falle>
</Bauteil>

</Bauteile>

<Konfig titel="Ein Datenbankabzug, der nicht still scheitern kann">

Die Form des nächtlichen Abzugs. Jeder der fünf Schritte steht für einen Fehler, der
sonst grün durchläuft — dieselben fünf, die der Prompt [„Das eigene Backup gegen sechs
Fragen prüfen“](/de/prompts/#backup-pruefen) abfragt.

```bash
#!/usr/bin/env bash
# Nächtlicher Datenbankabzug — die Form, nicht das Original.
set -euo pipefail          # bricht ab, wenn IRGENDEIN Glied scheitert,
                           # nicht nur das letzte in der Kette

ZIEL="<abzugsordner>"
NAME="<dienst>-$(date +%F).sql.gz"
MINDEST_BYTES=<untergrenze>   # aus den bisherigen Abzügen ableiten
GENERATIONEN=7

# 1. In eine .part-Datei schreiben — der endgültige Name kommt zuletzt
docker exec <datenbank-container> pg_dump -U <benutzer> <datenbank> \
  | gzip > "$ZIEL/$NAME.part"

# 2. Einmal vollständig lesen: ein halbes Archiv fällt hier auf,
#    nicht erst beim Wiederherstellen
gzip -t "$ZIEL/$NAME.part"

# 3. Mindestgrösse: ein leerer Abzug ist auch ein gültiges Archiv
groesse=$(stat -c %s "$ZIEL/$NAME.part")
if [ "$groesse" -lt "$MINDEST_BYTES" ]; then
  echo "Abzug zu klein: $groesse Bytes" >&2
  exit 1
fi

# 4. Erst jetzt der endgültige Name — mv im selben Dateisystem ist atomar
mv "$ZIEL/$NAME.part" "$ZIEL/$NAME"

# 5. Sieben Generationen behalten
ls -1t "$ZIEL"/<dienst>-*.sql.gz | tail -n +$((GENERATIONEN + 1)) | xargs -r rm --
```

⚠️ Ein Probelauf dieses Skripts verbraucht eine Generation. Und was es nicht kann:
melden, dass es **gar nicht gelaufen** ist. Dafür braucht es einen zweiten Blick von
aussen — die Zählung, ob der Abzug von heute überhaupt da ist.

</Konfig>

<Konfig titel="Die Zeile, die das Archiv ohne die Software lesbar hält" id="dateibaum">

Paperless-ngx legt Dokumente sonst unter internen Nummern ab. Diese eine Einstellung
macht daraus einen Baum aus Absender, Jahr und Titel — den ein Mensch auch dann noch
versteht, wenn die Software längst weg ist.

```text
PAPERLESS_FILENAME_FORMAT={{ correspondent }}/{{ created_year }}/{{ title }}
```

Gesetzt wird sie als Umgebungsvariable des Containers. Laut Dokumentation gilt sie für
neue Ablagen; bereits abgelegte Dokumente zieht der mitgelieferte Befehl
`document_renamer` nach. **Danach einmal in den Ordner schauen**, ob der Baum wirklich so
aussieht — die Einstellung zu setzen ist nicht dasselbe wie ihre Wirkung gesehen zu haben.

</Konfig>
